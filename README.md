# Портфолио Александры Брагинской

Сайт на React, TypeScript и Vite: галерея работ, отдельная страница каждой работы, выставки, новости и соцсети. Изменения публикуются в GitHub Pages после push в `main` и успешного выполнения GitHub Actions.

## Где что менять

Все пути ниже указаны от корня репозитория.

| Что обновить                                             | Где менять                                                                                                  |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Название, описание, год, материалы, размер и цена работы | `public/data/<id>.json`                                                                                     |
| Оригинал изображения работы                              | `public/img/<id>.jpg`                                                                                       |
| Состав и порядок галереи                                 | `public/gallery.json`, правила ниже                                                                         |
| Превью работ                                             | `public/img/preview/`, создаются командой `pnpm previews`                                                   |
| Заголовок, описание, дата и ссылка новости               | `public/data/news/<id>.json`                                                                                |
| Обложка новости                                          | `public/img/news/<id>.jpg`                                                                                  |
| Состав и порядок новостей                                | `public/news.json`, первая запись показывается первой                                                       |
| Текст «О художнице» и ссылки на соцсети                  | `src/components/Editorial.tsx`                                                                              |
| Выставки и достижения                                    | Массив `slides` в `src/components/Carousel.tsx`                                                             |
| Имя и подпись на первом экране                           | `src/components/Hero.tsx`                                                                                   |
| Аватарка канала                                          | `public/img/channel-avatar.jpg`                                                                             |
| Название, описание и ссылка канала над новостями         | Блок `channel-intro` в `src/main.tsx`                                                                       |
| Названия разделов, вступление галереи, подпись в подвале | `src/main.tsx`                                                                                              |
| Пункты навигации                                         | Массив `links` в `src/components/Navigation.tsx`                                                            |
| Название вкладки и описание сайта для поиска             | `index.html` и `painting.html`; заголовок конкретной работы формируется в `src/components/PaintingPage.tsx` |
| Оформление и адаптивность                                | `src/styles/`                                                                                               |
| Параллакс на ПК                                          | `src/hooks/useParallax.ts`                                                                                  |
| Автоматическая сборка и публикация                       | `.github/workflows/pages.yml`                                                                               |

Не редактируйте `dist/`: это результат сборки, следующая сборка его перезапишет. Контент JSON включается в приложение при сборке; загрузить один JSON на хостинг без пересборки недостаточно.

## Добавить работу

1. Придумайте уникальный ID: латинские буквы в нижнем регистре, цифры и `_`, без пробелов. Например, `novaya_rabota`. После публикации ID лучше не менять: он используется в ссылках.
2. Положите настоящее JPEG-изображение в `public/img/novaya_rabota.jpg`. Простое переименование PNG в JPG не конвертирует файл.
3. Создайте `public/data/novaya_rabota.json`:

```json
{
  "title": "Новая работа",
  "year": 2026,
  "materials": "Акрил",
  "size": "Холст 40×50",
  "price": "Цена: 15 000 руб.",
  "description": "Описание работы."
}
```

4. Добавьте `"novaya_rabota"` в конец массива `public/gallery.json`. Между элементами нужна запятая, после последнего элемента запятой быть не должно.
5. Выполните `pnpm previews`. Команда заново создаёт превью всех работ из списка: `<id>-480.webp` и `<id>-900.webp` в `public/img/preview/`.
6. Проверьте карточку и страницу `painting.html?id=novaya_rabota`. В коммит должны попасть JSON, оригинал, оба превью и изменение списка.

`year` необязателен: если год неизвестен, поле можно опустить. Остальные поля из примера обязательны. Если значение `price` начинается со слова «Цена», сайт выводит подпись «Цена» и убирает повторное слово, двоеточие и пробелы из значения. Например, `Цена: 15 000 руб.` отображается одной строкой «Цена: 15 000 руб.». Для текста `Находится в частной коллекции.` подпись будет «Статус».

### Порядок работ

Текущий порядок отображения: **последние четыре ID из `public/gallery.json` в обратном порядке, затем все остальные ID в исходном порядке списка**. Это правило находится в `src/content.ts`.

Например, список `[a, b, c, d, e, f]` показывается как `[f, e, d, c, a, b]`. Добавление ID в конец помещает новую работу наверх и сдвигает состав первой четвёрки. Год создания не участвует в сортировке. Чтобы изменить порядок старых работ, переставляйте ID в части списка перед последними четырьмя.

Для замены изображения используйте тот же путь и заново выполните `pnpm previews`. Для удаления работы уберите ID из списка, затем удалите её JSON, оригинал и оба превью, если они больше не нужны.

## Добавить новость

1. Выберите уникальный ID, например `vystavka2027`.
2. Создайте `public/data/news/vystavka2027.json`:

```json
{
  "title": "Название выставки",
  "description": "Краткое описание события.",
  "date": "2027-04-12",
  "link": "https://t.me/artalexatorsher/1234"
}
```

3. Положите обложку в `public/img/news/vystavka2027.jpg`. Удобный формат — 1000×625 пикселей: сайт отображает обложки в пропорции 8:5 и обрезает лишнее по краям. Важные детали лучше оставлять ближе к центру.
4. Добавьте ID в **начало** `public/news.json`, если новость должна быть первой. Новости автоматически не сортируются по дате.

Если точная дата неизвестна, укажите `"date": ""`: дата не будет показана. Не придумывайте даты. Поле `link` необязательно; для внешних ссылок используйте HTTPS. Команда `pnpm previews` обрабатывает только работы, не обложки новостей.

Для удаления новости уберите ID из `public/news.json` и удалите соответствующие JSON и изображение.

## Обновить контакты и первый экран

Соцсети находятся в `src/components/Editorial.tsx`. Кнопка «Связаться с художницей» на странице работы ведёт на `index.html#contacts`. Если меняете ID раздела контактов, обновите также эту ссылку и навигацию. Личный номер телефона или личный Telegram сейчас не указан.

Мобильная навигация остаётся в одну строку: пункты, не поместившиеся целиком, скрываются. Кнопка «Меню» справа снизу возвращает к ней. На ПК меню закрепляется сверху.

Первый экран использует исходные слои `public/img/layer-1.png` … `layer-4.png`. На экранах шире 900px для объектов 1–3 используются отдельные `hero-object-1.webp` … `hero-object-3.webp` без прозрачных полей; фон берётся из `layer-4.png`. При замене композиции обновляйте обе версии и проверяйте их размещение в `src/styles/hero.css`. `pnpm previews` эти изображения не генерирует. Параллакс работает только на ПК с точным указателем и отключается при системном уменьшении движения.

## Запуск и проверка

Нужны Node.js 22.18+ и pnpm 11.25.0; в CI используется Node.js 24. Если pnpm не установлен, установите его командой `npm.cmd install --global pnpm@11.25.0` и откройте новый терминал.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Локальный сайт: http://127.0.0.1:5173/ . В режиме разработки изменения подхватываются автоматически.

Перед публикацией:

```sh
pnpm format
pnpm format:check
pnpm test
pnpm build
```

`pnpm format` форматирует исходники; изменённые JSON в `public/data/` при необходимости форматируйте отдельно: `pnpm exec prettier --write public/data/novaya_rabota.json`. Проверки данных находят пропущенные поля, изображения и превью. Сборка проверяет TypeScript и создаёт `dist/`.

Для браузерных проверок после сборки:

```sh
pnpm exec playwright install chromium
pnpm test:e2e
```

Тесты проверяют настольную и мобильную версии. Отчёт сохраняется в `playwright-report/`, ошибки и трассировки — в `test-results/`. При изменении количества карточек или правил отображения обновляйте соответствующие ожидания в `tests/site.spec.ts`. Отдельные проверки последней партии правок также содержат ожидаемые цены и порядок работ.

Для просмотра production-сборки используйте `pnpm preview`. Дополнительно проверьте сайт на реальном телефоне, включая браузер внутри Telegram: эмуляция не воспроизводит все особенности iOS.

## Публикация в GitHub Pages

После проверки просмотрите `git diff`, добавьте нужные файлы, создайте коммит и выполните `git push origin main`. Если в удалённой ветке есть чужие изменения, сначала согласуйте их с локальной работой; не используйте force push для обхода конфликта.

Workflow `.github/workflows/pages.yml` запускается после push в `main` и вручную через GitHub Actions. Он устанавливает зависимости по lock-файлу, проверяет форматирование, запускает `pnpm test`, собирает сайт и публикует `dist/`. При ошибке проверок новая версия не публикуется. Playwright в CI сейчас не запускается.

Откройте вкладку Actions репозитория и дождитесь успешного завершения `Deploy to GitHub Pages`. В настройках Pages источником должен быть **GitHub Actions**.

Сайт: https://faust-man.github.io/Alexandra-Braginskaya/ . Репозиторий: https://github.com/faust-man/Alexandra-Braginskaya . Сборка поддерживает размещение в подкаталоге и прямые ссылки `painting.html?id=…`.

## Кеш и служебные файлы

В production изображения кешируются Service Worker в Cache Storage браузера: до 80 изображений, только с этого сайта. При повторном запросе картинка показывается из кеша и проверяется обновление в фоне; новая версия используется при следующем запросе. После замены картинки по прежнему адресу первое открытие может показать старую копию. Для немедленной проверки очистите данные сайта в браузере. HTML и код приложения этот Service Worker не кеширует. В `pnpm dev` он не регистрируется.

`node_modules/`, `dist/`, отчёты тестов и `work_notes/` не отправляются в Git. Полезные рабочие заметки сохраняются в `work_notes/` локально. Единственный lock-файл — `pnpm-lock.yaml`: при обновлении зависимостей добавляйте его в тот же коммит, что и `package.json`.

Для текущего сайта секреты и переменные окружения не нужны. Не кладите пароли, токены и персональные данные в `public/` или переменные `VITE_*`: они доступны посетителям.
